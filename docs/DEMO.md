# TSUMUGI 90秒デモ台本

実測（2026-10-17、ai& deepseek-v4-flash / v4.1-flash、ローカル）：初回解析 約8〜14秒、出典追加の再評価 約13〜18秒、無効化 約8〜13秒。モデル出力は温度0でも完全には固定されないため、本番前に一度通しで流すこと。

## 事前準備（発表5分前）

1. `npm run backend` と `npm run demo` を起動し、http://127.0.0.1:3000 を開く。
2. `curl -s 127.0.0.1:8000/api/health` で `"configured":true` を確認。
3. 一度通しで流して ai& と Neo4j の疎通を確認し、「New analysis」でトップに戻しておく。
4. ブラウザのズームは 90〜100%。根拠パネルが右に開く幅（1280px以上）を確保する。

## 台本

| 時間 | 操作 | 話すこと |
| --- | --- | --- |
| 0〜15秒 | **Try an example** → **Explore the context** | 祭りの写真に「祇園祭は7月を通して行われる。この写真は2026年に京都で撮影された」という合成キャプションを付けました。写真だけでは確認できない場所と年が断定されています。 |
| 15〜35秒 | 解析中の表示（Weaving context）→ 結果表示 | AIは画像の観察と、文章の主張を分けて抽出します。下部のActivityは実際のモデル呼び出しに連動しています。 |
| 35〜55秒 | 画像の枠 **01/02** をクリック → 主張 **01** をクリック | 「見えること」は画像領域にひも付きます。ただし観察は場所や日付の証拠にはなりません。主張は原文の該当箇所がハイライトされ、根拠がないので Unresolved です。自称の信頼度%は出しません。 |
| 55〜75秒 | **Add evidence** → **Use the Kyoto tourism excerpt** → **Add & re-evaluate** | 京都市観光協会のFAQの抜粋を出典として登録します。URLは自動取得せず、登録したテキストだけを根拠にします。 |
| 75〜90秒 | **What changed** を見せる → **See why** で引用表示 → **Disable** | 「7月開催」だけが Confirmed に変わり、引用元の文言をそのまま確認できます。一方、写真の場所と年は未解決のままです。行事の説明が得られたことと、写真がその行事だと同定できたことは別だからです。出典を無効化すると、判定は Unresolved に戻ります。 |

締めの一言：「翻訳ではなく文脈を紡ぐ。分かることと、まだ分からないことを、根拠付きで伝えます。」

## 想定質問

- **なぜ写真の場所はConfirmedにならないのか**：一般的な祭りの説明は特定の写真の撮影地・撮影年を証明しないため、意図的に保留にしている（`photo_provenance_missing`）。
- **モデルが引用を捏造したら**：モデルは登録済みの passage ID しか選べず、引用文はサーバーが保存テキストから取り出す。存在しないIDは `invalid_citation` として拒否する。
- **Neo4jの役割**：観察・主張・出典・判定・説明の依存関係をrevisionごとに保存し、出典の無効化がどの判定に影響するかを追跡する。グラフ詳細ビューは未実装。
- **未実装**：YOLO/SAM3による領域分割（枠はVLMの候補）、URL自動取得、公開デプロイ、出力キャッシュ。

## トラブル時

- 「Needs attention」と表示された場合：**Retry** を押す。直前の検証済み表示は保持される。
- ai& が応答しない場合：`.runtime/last-smoke.json` にある直近のスモーク結果（実出力）を見せ、「ライブ実行結果の記録」と明示して説明する。キャッシュをライブ結果として見せない。
- 解析が75秒を超えるとfailedになる。サーバー再起動中のジョブもfailedとなり、Retryで再開できる。
