# TSUMUGI 90秒デモ台本

実測（2026-10-17、ai& deepseek-v4-flash / v4.1-flash ＋ 独立検証 qwen3.8-27b、Neo4j Aura、ローカル、各3回の中央値）：初回解析 約3.6秒（最初の主張は約1.4秒、画像の観察は約1.8秒で表示）、出典追加の再評価 約4.3秒、無効化 約0.5秒。ai& の応答時間は呼び出しごとにばらつき、1回の呼び出しで10秒以上かかることもある。本番前に一度通しで流すこと。

## 事前準備（発表5分前）

1. `npm run up` で一括起動し（本番ビルド込みで約15秒）、http://127.0.0.1:3000 を開く。終了は `npm run down`、状態確認は `npm run status`。
2. `npm run status` で backend が `ready (ai& key configured)` になっていることを確認。
3. 一度通しで流して ai& と Neo4j の疎通を確認し、「New analysis」でトップに戻しておく。
4. ブラウザのズームは 90〜100%。根拠パネルが右に開く幅（1280px以上）を確保する。表示言語はヘッダーの **Both**（英日併記）にしておく。

## 想定質問

- **なぜ写真の場所はConfirmedにならないのか**：一般的な祭りの説明は、特定の写真の撮影地・撮影年を証明しないため、意図的に保留にしている（`photo_provenance_missing`）。写真2の手書き文字や、Commons 上の撮影年（1905年）もモデルには証拠として渡していない。
- **モデルが引用を捏造したら**：モデルは登録済みの passage ID しか選べず、引用文はサーバーが保存テキストから取り出す。存在しないIDは `invalid_citation` として拒否する。主張と画像の対応付けでも、存在しない observation ID は捨てる。
- **独立検証とは**：説明文は DeepSeek が英日で書き、qwen（`AIAND_CHECK_MODEL`）が「英文が根拠に沿っているか」と「日本語が英文に忠実か」を確認する。却下されたとき、または検証できなかったときは、コードで決めた英日の定型文に戻す。
- **Neo4jの役割**：Asset／Region／Observation／Claim／Assessment／Passage／Source／Explanation／ToolRun を、型付きの関係でrevisionごとに保存する。画面の Graph はNeo4jから読み出したもの。出典を無効化するときは、Neo4j で影響範囲をたどり、該当する主張だけを再検証する。
- **英日併記**：観察・主張・判定理由・説明は、モデルが英日を同時に出力する。出典の引用は原文が正で、日本語は「参考訳」と明記して表示する。
- **未実装**：YOLO/SAM3による領域分割（枠はVLMの候補）、URL自動取得、公開デプロイ。

## トラブル時

- 「Needs attention」と表示された場合：**Retry** を押す。直前の検証済み表示は保持される。
- ai& が応答しない場合：`.runtime/last-smoke.json` にある直近のスモーク結果（実出力）を見せ、「ライブ実行結果の記録」と明示して説明する。キャッシュをライブ結果として見せない。
- Graph が「Local snapshot (Neo4j unreachable)」と表示された場合：Neo4j からの読み出しに失敗している。グラフは SQLite に保存した同じ revision のデータから描画している（書き込みに失敗した revision は completed にならない）。
- 解析が75秒を超えるとfailedになる。サーバー再起動中のジョブもfailedとなり、Retryで再開できる。
